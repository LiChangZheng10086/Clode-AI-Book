# Clode AI Book — 使用教程

## 1. 启动系统

### 第一步：启动基础设施（Docker）

```bash
# 确保 PostgreSQL 和 Redis 容器在运行
docker start pgsql my-redis
```

### 第二步：启动后端

```bash
cd /Users/mac/workspace/ai/clode-ai-book/backend
source .venv/bin/activate
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

### 第三步：启动前端

```bash
cd /Users/mac/workspace/ai/clode-ai-book/frontend
npm run dev
```

打开浏览器访问 **http://localhost:5173**

---

## 2. 使用流程

整个系统分为 **5 个阶段**：

```
创建小说 → 预处理 → 审核大纲/设定 → 逐章写作 → 追踪钩子
```

---

### 阶段一：创建小说

1. 打开首页 `http://localhost:5173`，看到创建表单
2. 填写：
   - **书名**：例如 `"逆天吞噬"`
   - **类型**（选填）：例如 `"仙侠/热血"`
   - **目标章节数**：例如 `100`
3. 点击 **"创建并开始预处理"**，自动跳转到预处理页面

---

### 阶段二：预处理（Agent 流水线）

这是核心阶段。你在预处理页面输入小说构思，4 个 Agent 依次运行：

**输入示例：**

```
大纲：少年林凡偶然获得一枚古戒，戒中有上古吞噬之力的传承。
      他从此踏上修仙之路，从底层小修士一步步崛起。
      第一卷：小镇觉醒 — 在小镇被欺压后，林凡激活古戒，踏上修炼之路。
      第二卷：宗门风云 — 进入青云宗，卷入宗门内部的权力斗争。
      第三卷：大陆争锋 — 宗门大战爆发，林凡成长为一方强者。

角色：主角林凡，16岁，孤儿，性格坚毅，不轻言放弃，但有时过于冲动。
      师傅青云真人，表面温和实则深藏不露。
      反派血魔老祖，为夺古戒不择手段。
      女主苏婉儿，青云宗大师姐，冷傲但善良。

世界观：修真世界，有练气→筑基→金丹→元婴→化神五大境界。
        丹药体系、宗门势力、上古遗迹、妖兽横行。
        古戒中的吞噬之力可以吞噬万物转化为修为，但代价是每次使用会消耗寿元。

风格：热血但不无脑，类似《凡人修仙传》的写实风格。
      不要过度描写打斗场景，注重人物内心和世界探索。
```

**Agent 执行顺序：**

| 顺序 | Agent | 做什么 | 预计耗时 |
|------|-------|--------|----------|
| 1 | A1 世界观 | 补全世界体系：地理、力量体系、势力、规则、历史 | 1-3 分钟 |
| 2 | A3 角色 | 设计主角/配角/反派/NPC 完整档案：性格、声线、关系网、角色弧 | 1-3 分钟 |
| 3 | A2 风格 | 量化写作参数：叙事视角、时态、句式偏好、禁用词列表 | 1-2 分钟 |
| 4 | 交叉验证 | 自动检测 A1/A2/A3 输出之间的一致性 | < 1 分钟 |
| 5 | A4 大纲 | 生成卷→章→场景三级大纲结构 | 2-5 分钟 |

**决策点交互：** 在 Agent 运行过程中，如果某个 Agent 遇到了需要你来决策的关键问题（比如"力量体系选修真还是魔法？"），页面会弹出选择界面。你选择一个方案后，管道继续。

---

### 阶段三：审核设定和大纲

预处理完成后，你应该依次审核：

1. **设定页** (`/project/:id/settings`)
   - 世界观 Tab：检查世界体系的完整性
   - 角色 Tab：检查角色档案是否合理
   - 风格 Tab：确认写作风格参数

2. **大纲页** (`/project/:id/outline`)
   - 浏览卷/章结构
   - 确认章节分配是否合理

---

### 阶段四：逐章写作

进入 **写作页** (`/project/:id/write`)，这是生成小说的主界面。

**每章的生成流程：**

```
生成大纲 → 确认大纲 → 撰写正文 → 自动润色 → 审核
                                              ↓
                                    通过 → 记忆更新 → 下一章
                                    不通过 → 自动修订 → 再审（最多3轮）
```

**操作流程：**

1. 确认章节编号（默认从第 1 章开始）
2. 点击 **"生成章节大纲"** → A5 生成场景级大纲
3. 审核大纲内容，满意后点击 **"确认大纲，开始写作"**
4. A6 撰写正文 → Polisher 自动去 AI 化润色 → A7 审核
5. 查看审核报告（8 项评分），如果显示"通过"则自动跳下一章
6. 如果审核不通过，点击 **"自动修正"** 让 A6 根据审核意见修改
7. 3 轮审核后仍未通过，可以点击 **"人工通过"** 强制放行

---

### 阶段五：追踪钩子

在 **钩子页** (`/project/:id/hooks`) 用看板视图管理伏笔：

| 列 | 含义 |
|----|------|
| 已播种 | 已埋下但尚未触发的伏笔 |
| 推进中 | 正在发展的伏笔 |
| 已回收 | 已完成的伏笔 |
| 逾期 | 超过计划回收章节但未完成的伏笔 |

## 3. 完整示例演示

以下用一个迷你小说（10 章）演示完整流程：

### 3.1 创建

书名：`测试小说`，类型：`玄幻`，目标章节：`10`

### 3.2 输入构思

```
大纲：一个普通少年穿越到异世界，发现自己有吞噬万物的能力。
      第1-3章：穿越觉醒，初试能力
      第4-7章：遇到伙伴，组队冒险
      第8-10章：面对第一个大反派，最终决战

角色：主角陈凡，25岁社畜穿越，性格幽默但关键时刻可靠
      女伴艾琳，精灵族弓箭手，冷酷但内心温柔

世界观：剑与魔法的异世界，有冒险者公会体系，五种魔法元素
风格：轻松搞笑，类似《为美好的世界献上祝福》
```

### 3.3 预处理

点击"开始分析"→ 等 4 个 Agent 依次完成 → 遇到决策点就选择 → 全部完成

### 3.4 开始写作

进入写作页 → 第 1 章点击"生成章节大纲"→ 确认大纲 → 等待写手/润色/审核 → 通过后点"下一章"

### 3.5 查看钩子

定期查看钩子看板，确保埋下的伏笔按计划回收

## 4. 常见问题

| 问题 | 解决 |
|------|------|
| 审核一直不通过 | 人工通过；检查大纲设定是否一致，可能是前面的设定有矛盾 |
| Agent 输出不够好 | 回到预处理页面重新运行，或在输入中给出更具体的描述 |
| 风格不像想要的 | 在输入中提供参考文本样例，或者手动编辑风格参数 |
| 向量模型没加载 | 首次运行会自动下载 BGE 模型（~1.3GB），之后缓存使用 |

## 5. API 直接调用

如果想绕过前端直接用 API：

```bash
# 创建小说
curl -X POST http://localhost:8000/api/novels/ \
  -H "Content-Type: application/json" \
  -d '{"title": "测试小说", "genre": "玄幻", "target_chapters": 10}'

# 查看所有小说
curl http://localhost:8000/api/novels/

# 预处理通过 WebSocket：ws://localhost:8000/api/ws/preprocess/{novel_id}
# 写作通过 WebSocket：ws://localhost:8000/api/ws/write/{novel_id}
```
